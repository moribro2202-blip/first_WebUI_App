# リリース統合スキル

本番環境へのデプロイ前に必要なチェックを一括で実行します。

## When to Use This Skill

- Webアプリをリリースする前
- 「/release」と入力された時
- 「リリース準備して」と依頼された時
- 本番デプロイする前

## ワークフロー

```
┌──────────────────┐
│ 1. バージョン確認  │ package.json のバージョン確認・更新
└────────┬─────────┘
         ▼
┌──────────────────┐
│ 2. 品質チェック   │ 型チェック・テスト・Lint
└────────┬─────────┘
         ▼
┌──────────────────┐
│ 3. ビルドテスト   │ npm run build でビルド確認
└────────┬─────────┘  ※ --skip-build でスキップ
         ▼
┌──────────────────┐
│ 4. デプロイチェック│ 環境変数・設定確認
└────────┬─────────┘
         ▼
┌──────────────────┐
│ 5. 変更履歴作成   │ CHANGELOG 更新
└────────┬─────────┘
         ▼
┌──────────────────┐
│ 6. リリースノート │ リリースノート作成
└──────────────────┘
```

## 引数

| 引数 | 説明 |
|------|------|
| `--version <x.y.z>` | リリースバージョンを指定 |
| `--skip-build` | ビルドテストをスキップ |
| `--quick` | 最小限のチェックのみ |

## 使用例

```bash
# フルチェック
/release

# バージョン指定
/release --version 1.2.0

# ビルドスキップ
/release --skip-build
```

## AI Assistant Instructions

### フェーズ1: バージョン確認

```bash
cat package.json | grep '"version"'
```

**セマンティックバージョニング:**
- `x.0.0` - メジャー（破壊的変更）
- `x.y.0` - マイナー（新機能追加）
- `x.y.z` - パッチ（バグ修正）

### フェーズ2: 品質チェック

```bash
# 型チェック
npx tsc --noEmit

# テスト
npm test

# Lint
npm run lint
```

**チェックリスト:**
- [ ] 型エラーなし
- [ ] テスト全件パス
- [ ] Lintエラーなし
- [ ] console.log 残存なし
- [ ] 開発用コード削除済み

### フェーズ3: ビルドテスト（--skip-build でスキップ）

```bash
npm run build
```

**確認事項:**
- [ ] ビルド成功
- [ ] ビルドエラーなし
- [ ] ビルドサイズが適切

### フェーズ4: デプロイチェック

| 項目 | 確認内容 |
|------|----------|
| 環境変数 | Vercel に本番用の値が設定済みか |
| ドメイン | カスタムドメイン設定済みか |
| メタデータ | title, description, OGP設定済みか |
| favicon | 設定済みか |
| Analytics | Firebase Analytics 設定済みか |

### フェーズ5: 変更履歴作成

`CHANGELOG.md` を更新:

```markdown
# Changelog

## [1.2.0] - 2024-01-20

### Added
- 新機能A を追加
- 新機能B を追加

### Changed
- 既存機能C を改善

### Fixed
- バグD を修正
```

### フェーズ6: リリースノート作成

```
v1.2.0 リリースノート

新機能:
- 〇〇機能を追加しました

改善:
- □□の動作を改善しました

バグ修正:
- ××の問題を修正しました
```

