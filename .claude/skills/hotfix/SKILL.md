# 緊急修正（Hotfix）スキル

本番環境の緊急バグ修正を迅速に行うためのワークフローです。

## When to Use This Skill

- 本番環境で緊急のバグが発生した時
- 「/hotfix」と入力された時
- 「緊急修正して」と依頼された時
- クリティカルなバグを即座に修正したい時

## ワークフロー

```
┌──────────────────┐
│ 1. 状況確認       │ 現在のブランチ・変更を退避
└────────┬─────────┘
         ▼
┌──────────────────┐
│ 2. hotfixブランチ │ main から hotfix/xxx を作成
└────────┬─────────┘
         ▼
┌──────────────────┐
│ 3. 修正実装       │ 最小限の修正のみ
└────────┬─────────┘
         ▼
┌──────────────────┐
│ 4. 緊急テスト     │ 影響範囲のみテスト
└────────┬─────────┘
         ▼
┌──────────────────┐
│ 5. 即時コミット   │ fix: プレフィックスで
└────────┬─────────┘
         ▼
┌──────────────────┐
│ 6. 緊急PR作成     │ 優先度高でPR作成
└──────────────────┘
```

## 引数

```
/hotfix <問題の簡潔な説明>
/hotfix ログインエラー
/hotfix --skip-test 決済処理エラー
```

| 引数 | 説明 |
|------|------|
| `<説明>` | 修正する問題の説明（必須） |
| `--skip-test` | テストをスキップ（超緊急時のみ） |
| `--no-stash` | 現在の変更を退避しない |

## AI Assistant Instructions

### フェーズ1: 状況確認・準備

1. 現在の作業を退避

```bash
# 未コミットの変更があれば退避
git stash save "WIP: hotfix前の作業"

# mainブランチに移動
git checkout main
git pull origin main
```

2. 緊急度を確認
```
⚠️ Hotfix モード開始

現在の状況:
- 退避した変更: あり (stash@{0})
- ベースブランチ: main
- 最新コミット: abc1234

続行しますか？
```

### フェーズ2: Hotfixブランチ作成

```bash
git checkout -b hotfix/問題の簡潔な説明
```

**命名規則:**
- `hotfix/login-crash` - ログインクラッシュ
- `hotfix/payment-error` - 決済エラー
- `hotfix/data-loss` - データ消失

### フェーズ3: 修正実装

**重要: 最小限の修正のみ**

```
🔧 Hotfix ルール

✅ やるべきこと:
- 問題の直接的な原因のみ修正
- 影響範囲を最小限に

❌ やってはいけないこと:
- リファクタリング
- 関連する改善
- 新機能の追加
- コードスタイルの変更
```

修正後の確認:
```bash
git diff
```

### フェーズ4: 緊急テスト

```bash
# 型チェック
npx tsc --noEmit

# 関連テストのみ実行
npx jest --findRelatedTests src/path/to/modified/file.ts

# または全テスト（時間があれば）
npm test
```

### フェーズ5: 即時コミット

```bash
git add .
git commit -m "fix: 問題の説明

- 原因: [根本原因]
- 対応: [修正内容]
- 影響: [影響範囲]

🚨 Hotfix

🤖 Generated with Claude Code"
```

### フェーズ6: 緊急PR作成

```bash
git push -u origin HEAD

gh pr create \
  --title "🚨 [Hotfix] 問題の説明" \
  --body "## 🚨 緊急修正

### 問題
- 発生している問題の説明
- 影響を受けるユーザー/機能

### 原因
- 根本原因の説明

### 修正内容
- 修正した内容

### テスト
- [x] 型チェック通過
- [x] 関連テスト通過
- [ ] 本番環境での動作確認

### リスク
- この修正による副作用の可能性

### ロールバック手順
必要な場合のロールバック方法

---
🚨 **緊急対応のためレビュー優先をお願いします**

🤖 Generated with Claude Code" \
  --label "hotfix,urgent"
```

## 完了時の出力

```
🚨 Hotfix PR作成完了！

📋 サマリー
├─ ブランチ: hotfix/login-crash
├─ 修正ファイル: 2件
├─ 変更行数: +5, -3
└─ PR: #99

🔗 PR URL: https://github.com/owner/repo/pull/99

⚠️ 次のステップ
1. レビュアーに緊急連絡
2. CIの結果を確認
3. 承認後、即座にマージ
4. 本番デプロイを確認

📝 作業復帰
hotfix完了後、元の作業に戻る:
  git checkout [元のブランチ]
  git stash pop
```

## 修正後の作業復帰

```bash
# 元のブランチに戻る
git checkout feature/xxx

# 退避した変更を復元
git stash pop

# mainの変更を取り込む（hotfix含む）
git rebase main
```

## エラー時の対応

### テスト失敗（緊急時）

```
⚠️ テストが失敗しましたが、緊急修正のため続行しますか？

選択肢:
1. テストを修正してから続行
2. --skip-test で続行（非推奨）
3. 中止
```

### コンフリクト発生

```
❌ mainブランチとコンフリクトが発生

対応:
1. コンフリクトを解決
2. git add .
3. git commit
4. /hotfix を再実行
```

## 禁止事項

- リファクタリングの実施
- 関係ない変更の混入
- テストスキップの乱用
- 十分な確認なしのマージ
