# 開発フロー統合スキル

タスク確認 → 実装 → 品質チェック → コミット → PR作成 までの一連の開発フローを統合管理します。

## When to Use This Skill

- 新機能の実装を開始する時
- 「/dev-flow」と入力された時
- 「開発フローで進めて」と依頼された時
- 機能実装からPR作成まで一気通貫で行いたい時

## ワークフロー概要

```
┌─────────────┐
│ 1. タスク確認 │ docs/tasks/ のToDoを確認・ステータス更新
└──────┬──────┘
       ▼
┌─────────────┐
│ 2. 実装準備   │ 要件定義確認・ブランチ作成（必要時）
└──────┬──────┘
       ▼
┌─────────────┐
│ 3. 実装      │ コード変更・要件チェックボックス更新
└──────┬──────┘
       ▼
┌─────────────┐
│ 4. 品質チェック │ TypeScript型チェック・テスト実行
└──────┬──────┘
       ▼
┌─────────────┐
│ 5. コミット   │ Conventional Commits形式で自動生成
└──────┬──────┘
       ▼
┌─────────────┐
│ 6. PR作成    │ GitHub MCP経由でPR作成
└─────────────┘
```

## 引数オプション

| 引数 | 説明 |
|------|------|
| `--skip-test` | テスト実行をスキップ |
| `--no-pr` | PR作成をスキップ（コミットまで） |
| `--no-commit` | コミットをスキップ（品質チェックまで） |
| `--quick` | タスク確認・ブランチ作成をスキップ |

## 使用例

```
/dev-flow                    # フルフロー実行
/dev-flow --skip-test        # テストスキップ
/dev-flow --no-pr            # PRなし（コミットまで）
/dev-flow --quick --no-pr    # 素早くコミットのみ
```

## AI Assistant Instructions

### フェーズ1: タスク確認（--quick でスキップ可）

1. `docs/tasks/` 配下のタスクファイルを確認
2. 現在作業中のタスクを特定
3. ステータスを 🟡 進行中 に更新
4. 依存関係を確認

```bash
# タスクファイル確認
ls docs/tasks/
```

### フェーズ2: 実装準備（--quick でスキップ可）

1. `docs/requirements/functional.md` で要件を確認
2. 必要に応じてfeatureブランチを作成

```bash
# ブランチ作成（必要時）
git checkout -b feature/機能名
```

### フェーズ3: 実装

1. 要件定義に基づいてコードを実装
2. `docs/requirements/functional.md` の該当チェックボックスを更新
3. 実装完了後、タスクファイルのToDoも更新

### フェーズ4: 品質チェック（--no-commit でここまで）

1. TypeScript型チェック実行

```bash
npx tsc --noEmit
```

2. テスト実行（--skip-test でスキップ可）

```bash
npm test
# または
npx jest
```

3. エラーがあれば修正してから次へ

### フェーズ5: コミット（--no-pr でここまで）

1. 変更内容を確認

```bash
git status
git diff
```

2. `/git-commit` スキルのルールに従ってコミット

```bash
git add .
git commit -m "feat: 機能説明

- 変更点1
- 変更点2

🤖 Generated with Claude Code"
```

### フェーズ6: PR作成

1. リモートにプッシュ

```bash
git push -u origin HEAD
```

2. GitHub MCP または gh CLI でPR作成

```bash
gh pr create --title "feat: 機能説明" --body "## 概要
- 変更内容の説明

## テスト
- [ ] 動作確認済み

🤖 Generated with Claude Code"
```

## 進捗報告フォーマット

各フェーズ完了時に以下の形式で報告:

```
✅ フェーズ1: タスク確認 完了
   - タスク: 001_認証機能
   - ステータス: 🟡 進行中

✅ フェーズ2: 実装準備 完了
   - ブランチ: feature/auth-login

🔄 フェーズ3: 実装 進行中
   ...
```

## エラー時の対応

### 型チェックエラー

```
❌ 型チェックでエラーが発生しました
   エラー内容: [詳細]

   修正してから再度 /dev-flow --quick を実行してください
```

### テスト失敗

```
❌ テストが失敗しました
   失敗したテスト: [テスト名]

   修正するか、--skip-test オプションで続行できます
```

### コミット失敗

```
❌ コミットに失敗しました
   原因: [詳細]

   手動で解決後、/dev-flow --quick --no-commit を実行してください
```

## 完了時の出力

```
🎉 開発フロー完了！

📋 サマリー
├─ タスク: 001_認証機能
├─ ブランチ: feature/auth-login
├─ コミット: abc1234
└─ PR: #123

🔗 PR URL: https://github.com/owner/repo/pull/123
```

## 禁止事項

- mainブランチへの直接コミット
- テスト未実行でのPR作成（明示的スキップ除く）
- 要件定義にない機能の追加
- コミットメッセージの英語化（指示がない限り日本語）
